1"""What the two to-do list drivers do the same way, in one place. 

2 

3``shopping_sync.py`` (auto-buy reminders mirrored onto a shopping list) and 

4``todo_list_sync.py`` (profile-filtered chores kept in step with household 

5lists) are two different state machines driving one API: somebody else's 

6``todo.*`` entity, read over ``todo.get_items`` and written with 

7``todo.add_item`` / ``update_item`` / ``remove_item``. Snapshotting lists 

8defensively, refusing to call a service the entity does not support, holding the 

9re-entrancy guard and the pass budget around a plan-and-apply loop, saying a 

10thing once rather than on every event — none of that is specific to either sync, 

11so it lives here, and each driver supplies only what genuinely differs: how it 

12resolves its targets, what it plans, how it applies that plan, and what an 

13inbound tick means. 

14 

15The three properties both drivers owe their callers are properties of this base: 

16 

17* **It never breaks its caller.** A pass runs off the back of a completion, a 

18 stock adjustment or a task event; a list that is unavailable, unloaded, or 

19 refuses new items must cost nothing more than a log line. Every outbound call 

20 is best-effort (the ``notifier`` precedent) and :meth:`async_sync` swallows 

21 whatever reaches it. 

22* **A failed call is retried, never compensated.** The planners hand back the 

23 bookkeeping as it will read once every operation has succeeded; anything that 

24 raised puts its entry back, so the next pass tries again. That restoration is 

25 each subclass's ``_apply``, because the ops it walks differ. 

26* **It reads a to-do list only when there is a reason to.** Each planner's 

27 ``needs_pass`` answers "has Home Keeper drifted from what it last wrote" from 

28 memory alone; only the surfaces watching the *other* side of the loop — a 

29 list's own state changes, the periodic sweep — force a read. 

30 

31Everything the log says is a class-level knob rather than a shared string: a 

32household reading its log should see "shopping list" or "synced to-do list", 

33whichever actually happened, and each driver keeps logging under its own module 

34name. 

35 

36``problem_sync.py`` is deliberately not a subclass. It mirrors ``binary_sensor`` 

37entities into tasks off the entity registry and a state listener, and never 

38reads or writes a to-do list at all — what it shares with these two is the pure 

39planner/HA-driver split, not a mechanism. 

40"""

68 """The Home-Assistant-facing half of a to-do list sync. 

69 

70 A subclass owns its own targets, planner and plan application; it implements 

71 :meth:`_sync_once` and sets the class-level strings below, which are the 

72 only things the shared paths say out loud.

76 # driver that produced it rather than from this base.

79 _unsettled_warning: ClassVar[str]

81 _failed_pass_message: ClassVar[str]

92 # what guarantees the loop ends whatever the lists do.

129 # only see Home Keeper's own side. Hence the forced pass. Our own writes

134 # ── the pass ───────────────────────────────────────────────────────────── 

135 async def async_sync(self, *, force: bool = False) -> None: 

136 """Bring the lists in step. Never raises. 

137 

138 *force* reads the lists even when Home Keeper's own state looks settled, 

139 which is the only way to notice the other side of the loop — an item 

140 ticked off on somebody's phone. 

141 """ 

142 if self._running: 

143 # Poked mid-pass — our own writes echoing back, or the completion 

144 # this pass just made. Fold it into the run already in flight instead 

145 # of nesting. 

146 self._pending = True 

147 return 

148 self._running = True 

149 self._pending = False 

150 try: 

151 for attempt in range(self._MAX_PASSES): 

152 again = await self._sync_once(force=force or attempt > 0) 

153 if not (again or self._pending): 

154 break 

155 self._pending = False 

156 else: 

157 # The budget exists so the loop always ends, not because ending 

158 # this way is fine: a converging sync settles in two passes. 

159 # Burning the whole budget means something is failing and 

160 # retrying — say so, rather than exiting quietly and leaving the 

161 # lists stale with no trace of why. 

162 self._logger.warning(self._unsettled_warning, self._MAX_PASSES) 

163 except Exception: # a broken list must never break what triggered us 

164 self._logger.exception(self._failed_pass_message) 

165 finally: 

166 self._running = False 

167 self._pending = False
